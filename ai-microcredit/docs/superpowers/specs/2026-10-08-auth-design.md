# Вход и личный кабинет

Пользователь согласовал собственную авторизацию: главная → вход → кабинет,
белый фон, чёрный текст, тестовые аккаунты test1/test1 и далее.

## Границы

Next.js обслуживает интерфейс и серверные обработчики; PostgreSQL уже настроен
в compose.yaml на localhost:5433. Не менять пароль Docker и не удалять том.
Самостоятельной регистрации, админки и автоматического кредитного скоринга нет.

## Данные и доступ

- users: UUID, уникальный нормализованный login, display_name, password_hash,
  account_status ACTIVE/BLOCKED, created_at.
- sessions: SHA-256 случайного 256-битного токена, user_id, created_at, expires_at.
  Абсолютный срок жизни 24 часа. Выход отзывает запись; повторный вход заменяет
  текущую сессию браузера. Действующий аккаунт проверяется при каждом чтении.
- credit_applications: UUID, user_id, PENDING/APPROVED/REJECTED/ISSUED, даты.
  Кабинет показывает последнюю заявку владельца. Нет заявки — отдельное состояние UI.
- login_rate_limits: счётчики по хешу нормализованного логина, плюс общий бюджет
  попыток. Атомарные окна PostgreSQL предотвращают обход параллельными запросами.

Пароли: scrypt N=32768,r=8,p=3, случайная соль, timingSafeEqual. Неизвестный
пользователь тоже проходит дорогую проверку. Формат ошибок одинаков для неверного
пароля, неизвестного и заблокированного пользователя.

Токен передаётся только через HttpOnly, SameSite=Lax, Path=/ cookie. Secure
определяется явно APP_ORIGIN; вне localhost требуется HTTPS. POST принимает только
JSON от точного APP_ORIGIN, запросы cross-site запрещены; тело ограничено 4 KiB.
Серверные запросы параметризованы. userId берётся из сессии, не из браузера.
Персональные ответы не кешируются. Секреты и тексты DB-ошибок не возвращаются клиенту.

## Тестовые данные

test1 — нет заявки; test2 — PENDING; test3 — APPROVED; test4 — REJECTED;
test5 — ISSUED. Пароль совпадает с login. Seed только с явным флагом
ALLOW_DEMO_SEED=true и не в production, не перезаписывает существующие аккаунты.
Миграции транзакционные, версионируемые и защищены advisory lock. Повторный seed
не добавляет дубликаты. Ни одна команда настройки не удаляет существующие данные.

## Приёмка

Проверить миграции и seed повторно, хеширование, неверные данные, SQL injection,
лимит входа, CSRF, успешный вход и cookie, защиту чужих данных, истечение,
блокировку аккаунта, выход и недействительность отозванного токена. Unit и SQL
integration через встроенный PostgreSQL (PGlite); build/lint/typecheck и живой
HTTP smoke. Docker-соединение проверить отдельно, не выдавать PGlite за Docker.
