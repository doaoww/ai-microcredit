# Authentication Implementation Plan

**Goal:** Реализовать согласованный вход, кабинет и повторяемую настройку БД.
**Architecture:** Next.js route handlers → auth service → параметризованный SQL;
серверные страницы читают пользователя по cookie. PostgreSQL в Docker.
**Tech Stack:** TypeScript, Next.js, pg, node:crypto, node:test, tsx, PGlite.
**Spec:** ../specs/2026-10-08-auth-design.md

## Global constraints
- Сохранить compose.yaml и пользовательские настройки WebStorm.
- Не удалять тома и не перезаписывать имеющиеся аккаунты.
- Только простые белые страницы с чёрным текстом.
- Демопароли test1/test1 … test5/test5 только для локальной разработки.

## Review focus
- Неверный/слишком большой JSON: 400/413 без хеширования и раскрытия деталей.
- Повторный seed не меняет пароль/статус существующего пользователя.
- Параллельный вход не обходит лимит; неизвестный login ограничен так же.
- Удалённая, истёкшая сессия и BLOCKED пользователь не получают данные.
- CSRF, подмена userId и кеширование не раскрывают чужие заявки.
